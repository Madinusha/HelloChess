# Отчёт по ДЗ 4 — VictoriaMetrics

## 1. Стек

- Приложение: HelloChess (Java 17, Spring Boot 3.4.1, PostgreSQL)
- TSDB: VictoriaMetrics Single (`victoria-metrics-single`, helm-релиз `vm-single`, ns `monitoring`)
- Сбор метрик: vmagent (`victoria-metrics-agent`, helm-релиз `vm-single-agent`, ns `monitoring`)
- Экспорт метрик приложения: Spring Boot Actuator + Micrometer (`micrometer-registry-prometheus`), endpoint `/actuator/prometheus` на выделенном порту 8081
- Экспорт метрик PostgreSQL: сайдкар `postgres-exporter` (v0.17.1) в поде Postgres, порт 9187
- Service discovery: vmagent через дефолтный job `kubernetes-pods` по аннотациям `prometheus.io/scrape|port|path`

## 2. Модель сбора — Pull

Используется Pull-модель: vmagent сам периодически (scrape_interval 15s) опрашивает таргеты, обнаруженные через kubernetes service discovery. Аннотации на подах:

```yaml
prometheus.io/scrape: "true"
prometheus.io/port: "8081"     # для приложения
prometheus.io/path: "/actuator/prometheus"
```

Метрики приложения доступны только внутри кластера: порт 8081 не опубликован ни в одном Service (NodePort у приложения только 8080). В Spring Boot 3.4 security-чейн применяется и к management-порту, поэтому в `SecurityConfig` добавлена отдельная цепочка `managementFilterChain` (@Order(1)), матчер — `request.getLocalPort() == 8081`: весь трафик management-порта открыт без авторизации, при этом через NodePort 8080 наружу метрики недоступны.

## 3. Рантайм-метрики

Spring Boot Actuator + `micrometer-registry-prometheus`: `/actuator/prometheus` отдаёт метрики JVM (память, GC, потоки), HTTP-запросов, WebSocket, HikariCP и др. К общим метрикам добавлен тег `application=HelloChess`.

## 4. Метрики PostgreSQL

Контейнер `postgres-exporter` добавлен сайдкаром к StatefulSet `postgres` (общее пространство портов пода — подключение через `localhost:5432`). Экспортирует `pg_up`, `pg_database_size_bytes`, `pg_stat_activity_*`, `pg_locks_*` и др.

## 5. Бизнес-метрики

| Метрика | Тип | Лейблы | Точка вставки |
|---|---|---|---|
| `chess_games_created_total` | counter | — | `GameSessionService.createSession` — создана партия |
| `chess_games_finished_total` | counter | `result=white\|black\|draw\|other` | `ChessService.createGameHistoryAndSave` — единая точка всех путей завершения (победа по мату, сдача, время) |
| `chess_moves_total` | counter | — | `ChessService.makeMove` — сделан ход |
| `chess_logins_total` | counter | `result=success\|failure` | `AuthEventListener`: `AuthenticationSuccessEvent` / `AbstractAuthenticationFailureEvent` |
| `chess_users_registered_total` | counter | — | `UserController.registerUser` |
| `chess_friendship_requests_total` | counter | — | `FriendshipService.sendFriendRequest` |
| `chess_friendship_requests_accepted_total` | counter | — | `FriendshipService.acceptFriendRequest` |
| `chess_lessons_tasks_completed_total` | counter | `stars=1..3` | `ProgressService.updateTaskProgress` — задание урока выполнено |
| `chess_users_online` | gauge | — | размер множества онлайна в `OnlineUsersService` |
| `chess_games_active` | gauge | — | размер карты сессий в `GameSessionService` |

## 6. Проверка сбора

```bash
# Проверка подов и сервисов
kubectl get pods -n monitoring
kubectl get svc -n monitoring

# Проброс портов
kubectl port-forward svc/vm-single-victoria-metrics-single-server -n monitoring 8428:8428
kubectl port-forward svc/vm-single-agent-victoria-metrics-agent -n monitoring 8429:8429

# Доступные метрики (в списке должны быть chess_*, pg_*, jvm_*)
curl "http://localhost:8428/api/v1/label/__name__/values"

# Конкретные метрики приложения и статус таргетов
curl "http://localhost:8428/api/v1/query?query=up"
curl "http://localhost:8428/api/v1/query?query=chess_users_registered_total"
curl "http://localhost:8428/api/v1/query?query=pg_up"
curl "http://localhost:8429/targets"
```
